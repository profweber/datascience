loc or iloc?

Every row has a label – the index shown on the left – and a position: first row, second row, … loc selects by label, iloc by integer position (memory aid: i for integer). As long as the index is 0, 1, 2, …, both give the same result. After sorting or filtering, they no longer do:

df = pd.DataFrame({"T": [25, 18, 31]})   # labels 0, 1, 2
s = df.sort_values("T")                  # order now: labels 1, 0, 2
s.loc[0]     # row with the LABEL 0 → T = 25
s.iloc[0]    # FIRST row            → T = 18

Ranges differ, too: df.loc[0:2] includes the end (labels 0, 1 and 2), df.iloc[0:2] does not (positions 0 and 1, as for Python lists). For time series, including the end is convenient: s.loc["2015-01-01":"2019-12-31"] contains 31 December.

Pitfall: and, or, not do not work on columns

Python’s and, or and not handle a single truth value. For masks – NumPy arrays and pandas columns – use &, | and ~, which work element by element, and put every condition in brackets:

single value mask (array, column)
and and &
or or \|
not not ~ 
df[(df["machine_id"] == "M4") & (df["shift"] == "night")]   # correct
df[df["machine_id"] == "M4" & df["shift"] == "night"]       # error: & binds before ==

not m on a mask raises an error (“the truth value of an array is ambiguous”), and ~True on a single value gives -2, because ~ is originally a bitwise operator on integers (newer Python versions warn about this).

With three arguments, np.where(m, a, b) selects values. With only one argument, np.where(m) does something different: it returns the positions where m is True. For positions, np.flatnonzero(m) is clearer.

.str and .dt: functions for every entry of a column

Text functions such as strip() work on a single text. To apply them to every entry of a column, pandas offers the accessor .str: s.str.strip(), s.str.lower(), s.str.startswith("produkt"). The column must contain text – hence s.astype(str).str.strip(). In the same way, .dt gives access to the parts of time stamps: s.dt.hour, s.dt.day_name(). For a time index, these are available directly: df.index.hour, df.index.dayofweek.

Pitfall: some functions exist twice with different meanings.

s = pd.Series(["1,5", "2,0"])
s.replace(",", ".")        # replaces entries that are exactly "," – here: no change
s.str.replace(",", ".")    # replaces "," inside every text – "1.5", "2.0"

Forgetting .str raises no error – the data simply remain unchanged.

Format codes for time stamps

In pd.to_datetime(s, format=...), every code stands for one complete field of the date. %Y always has four digits; the two-digit codes also accept a single digit when reading, so %d/%m/%Y reads 19/07/2008 as well as 1/8/2008:

Code Meaning Digits Example
%Y year 4 2025
%y year without century 2 25
%m month 2 04
%d day 2 11
%H hour (00–23) 2 13
%M minute 2 05
%S second 2 00

All other characters (-, ., :, blanks) must appear in the format exactly as in the data. Upper and lower case matter: %m is the month, %M the minute – a classic error that often raises no error message. Other tools write formats with letters instead, e.g. yyyy-mm-dd hh:mm in Excel or YYYYMMDDHH24 in the DWD documentation; such formats have to be translated.

Method chaining – and why pandas makes it possible

In energy.set_index("date").sort_index(), the second method is applied directly to the result of the first. This works because of three design decisions in pandas:

  1. Methods return a new object and leave the original unchanged. df.sort_values("a") returns a sorted copy; df stays as it is. Plain Python does the opposite for lists: values.sort() sorts the list itself and returns None – so values.sort().reverse() fails, while df.sort_values("a").head() works.
  2. The type stays the same. A table becomes a table, a column a column – so the next method always fits. .str and .dt also return a column.
  3. Methods instead of statements. An assignment such as df["temp_K"] = df["temp_C"] + 273.15 cannot be chained; df.assign(temp_K=df["temp_C"] + 273.15) returns a new table with the additional column. For the same reason, avoid the older option inplace=True: it changes the table itself and returns None, which breaks the chain.

Returning new tables might sound expensive. Since pandas 3.0 (“copy-on-write”), however, data are only copied when they are actually changed.

Many NumPy functions also exist as pandas methods – s.abs(), s.median(), s.std(). For pandas data, prefer the methods: they fit into a chain, and they skip missing values, which NumPy functions do not:

s = pd.Series([1, -4, np.nan, 3])
s.abs().median()            # 3.0 – pandas skips the missing value
np.median(np.abs(s))        # nan – one missing value makes the result missing

The standard deviation differs, too: s.std() divides by \(n-1\) (sample standard deviation, Chapter 2), np.std(...) by \(n\) unless you write ddof=1.

For longer chains, put the whole expression in brackets – inside brackets, Python continues on the next line – and write one step per line:

daily = (weather
         .dropna()            # remove rows with missing values
         .resample("D")       # group by day
         .mean())             # one mean per day

Chains are compact; separate steps are easier to check. A good habit: build a chain step by step, and if it fails, remove the last steps until it works again – this shows which step causes the error.

pandas, seaborn and Matplotlib

pandas and seaborn do not draw themselves – they call Matplotlib. These three lines produce essentially the same line plot:

ax.plot(df.index, df["Appliances"], lw=0.3)        # Matplotlib
df["Appliances"].plot(ax=ax, lw=0.3)                # pandas
sns.lineplot(x=df.index, y=df["Appliances"], ax=ax) # seaborn

pandas takes the x-axis from the index (a time index gives a date axis) and draws one line per column, labelled with its name. Matplotlib options such as lw, alpha, color or label are passed on. With ax=..., pandas and seaborn draw into an existing field created by plt.subplots; without it, they create a new figure. Both return this field (ax), so you can continue with the usual Matplotlib commands, e.g. ax.set(ylabel="...").

Rule of thumb: pandas for quick plots directly from a table, seaborn for statistical plots (histogram, box plot, heatmap), Matplotlib via ax for fine-tuning.

## Pitfall: `and`, `or`, `not` do not work on columns
Python's `and`, `or` and `not` handle a *single* truth value. For masks – NumPy arrays and pandas columns – use `&`, `|` and `~`, which work element by element, and put every condition in brackets:

| | single value | mask (array, column) |
| --- | --- | --- |
| and | `and` | `&` |
| or | `or` | `\|` |
| not | `not` | `~` |

```python
df[(df["machine_id"] == "M4") & (df["shift"] == "night")]   # correct
df[df["machine_id"] == "M4" & df["shift"] == "night"]       # error: & binds before ==
```

`not m` on a mask raises an error ("the truth value of an array is ambiguous"), and `~True` on a single value gives `-2`, because `~` is originally a bitwise operator on integers (newer Python versions warn about this).
:::

## `.str` and `.dt`: functions for every entry of a column
Text functions such as `strip()` work on a *single* text. To apply them to every entry of a column, pandas offers the accessor `.str`: `s.str.strip()`, `s.str.lower()`, `s.str.startswith("produkt")`. The column must contain text – hence `s.astype(str).str.strip()`. In the same way, `.dt` gives access to the parts of time stamps: `s.dt.hour`, `s.dt.day_name()`. For a time *index*, these are available directly: `df.index.hour`, `df.index.dayofweek`.

Pitfall: some functions exist twice with different meanings.

```python
s = pd.Series(["1,5", "2,0"])
s.replace(",", ".")        # replaces entries that are exactly "," – here: no change
s.str.replace(",", ".")    # replaces "," inside every text – "1.5", "2.0"
```

Forgetting `.str` raises no error – the data simply remain unchanged.
:::

## Format codes for time stamps
In `pd.to_datetime(s, format=...)`, every code stands for one complete field of the date. `%Y` always has four digits; the two-digit codes also accept a single digit when reading, so `%d/%m/%Y` reads `19/07/2008` as well as `1/8/2008`:

| Code | Meaning | Digits | Example |
| --- | --- | --- | --- |
| `%Y` | year | 4 | `2025` |
| `%y` | year without century | 2 | `25` |
| `%m` | month | 2 | `04` |
| `%d` | day | 2 | `11` |
| `%H` | hour (00–23) | 2 | `13` |
| `%M` | minute | 2 | `05` |
| `%S` | second | 2 | `00` |

All other characters (`-`, `.`, `:`, blanks) must appear in the format exactly as in the data. Upper and lower case matter: `%m` is the month, `%M` the minute – a classic error that often raises no error message. Other tools write formats with letters instead, e.g. `yyyy-mm-dd hh:mm` in Excel or `YYYYMMDDHH24` in the DWD documentation; such formats have to be translated.

Formats you will meet in practice:

| Data look like | Typical source | Reading in pandas |
| --- | --- | --- |
| `2025-04-11 13:00:00`, `2025-04-11T13:00:00+02:00` | international standard ISO 8601: databases, web services, modern loggers | `pd.to_datetime(s, format="ISO8601")` |
| `11.04.2025 13:00` | German software, Excel exports | `format="%d.%m.%Y %H:%M"` |
| `2025041113` | compact formats of older systems, e.g. the DWD | `format="%Y%m%d%H"` (text, not number) |
| `1744376400` | seconds since 1 January 1970 (Unix time): sensors, IoT, log files | `pd.to_datetime(s, unit="s")` |
:::

## Method chaining – and why pandas makes it possible
In `energy.set_index("date").sort_index()`, the second method is applied directly to the result of the first. This works because of three design decisions in pandas:

1. **Methods return a new object and leave the original unchanged.** `df.sort_values("a")` returns a sorted copy; `df` stays as it is. Plain Python does the opposite for lists: `values.sort()` sorts the list itself and returns `None` – so `values.sort().reverse()` fails, while `df.sort_values("a").head()` works.
2. **The type stays the same.** A table becomes a table, a column a column – so the next method always fits. `.str` and `.dt` also return a column.
3. **Methods instead of statements.** An assignment such as `df["temp_K"] = df["temp_C"] + 273.15` cannot be chained; `df.assign(temp_K=df["temp_C"] + 273.15)` returns a new table with the additional column. For the same reason, avoid the older option `inplace=True`: it changes the table itself and returns `None`, which breaks the chain.

Returning new tables might sound expensive. Since pandas 3.0 ("copy-on-write"), however, data are only copied when they are actually changed.

Many NumPy functions also exist as pandas methods – `s.abs()`, `s.median()`, `s.std()`. For pandas data, prefer the methods: they fit into a chain, and they skip missing values, which NumPy functions do not:

```python
s = pd.Series([1, -4, np.nan, 3])
s.abs().median()            # 3.0 – pandas skips the missing value
np.median(np.abs(s))        # nan – one missing value makes the result missing
```

The standard deviation differs, too: `s.std()` divides by $n-1$ (sample standard deviation, Chapter 2), `np.std(...)` by $n$ unless you write `ddof=1`.

For longer chains, put the whole expression in brackets – inside brackets, Python continues on the next line – and write one step per line:

```python
daily = (weather
         .dropna()            # remove rows with missing values
         .resample("D")       # group by day
         .mean())             # one mean per day
```

Chains are compact; separate steps are easier to check. A good habit: build a chain step by step, and if it fails, remove the last steps until it works again – this shows which step causes the error.
:::

## pandas, seaborn and Matplotlib
pandas and seaborn do not draw themselves – they call Matplotlib. These three lines produce essentially the same line plot:

```python
ax.plot(df.index, df["Appliances"], lw=0.3)        # Matplotlib
df["Appliances"].plot(ax=ax, lw=0.3)                # pandas
sns.lineplot(x=df.index, y=df["Appliances"], ax=ax) # seaborn
```

pandas takes the x-axis from the index (a time index gives a date axis) and draws one line per column, labelled with its name. Matplotlib options such as `lw`, `alpha`, `color` or `label` are passed on. With `ax=...`, pandas and seaborn draw into an existing field created by `plt.subplots`; without it, they create a new figure. Both return this field (`ax`), so you can continue with the usual Matplotlib commands, e.g. `ax.set(ylabel="...")`.

Rule of thumb: pandas for quick plots directly from a table, seaborn for statistical plots (histogram, box plot, heatmap), Matplotlib via `ax` for fine-tuning.
:::
